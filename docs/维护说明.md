# SN 码查询 — 产品料号维护说明

本文档面向**非开发人员**。日常维护只需要修改一个文件：`data/products.json`。

**新增 SN 码详细教程：** [如何添加SN码.md](./如何添加SN码.md)

---

## 你需要做什么

当有新显卡型号、或需要修改已有型号名称时：

1. 登录 GitHub
2. 打开本仓库的 `data/products.json`
3. 在对应区域新增或修改一行
4. 保存并提交（Commit）

提交成功后，网站会在 1～2 分钟内自动更新。

> **说明：** 本网站托管在 **GitHub Pages** 上，域名是 `sn.zephyrsz.com`。你在 GitHub 上提交代码后，GitHub 会自动重新发布网站，无需手动上传文件。

## 操作步骤（GitHub 网页）

### 第一步：进入文件

1. 打开 GitHub 并登录
2. 进入 `product-info` 仓库
3. 依次点击文件夹：`data` → `products.json`

### 第二步：编辑

1. 点击文件右上角的 **铅笔图标**（Edit this file）
2. 找到需要修改的区域（见下方说明）
3. 修改内容

### 第三步：保存

1. 滚动到页面底部
2. 在 **Commit changes** 填写说明，例如：`新增 Z5801G 料号`
3. 点击 **Commit changes**

## 文件结构说明

`products.json` 里有三个数组：

| 数组名 | 用途 | 什么时候用 |
|--------|------|------------|
| `oldRules` | 旧规则 SN | 老款 SN，料号以 `ZF`、`LH` 等开头 |
| `newRules` | 新规则 SN | 2025 年后的新 SN，料号以 `Z` 开头 |
| `exceptions` | 特例 SN | 某个 SN 需要固定显示结果，不走自动解析 |

---

## 新增普通料号

### 新 SN（放进 `newRules`）

在 `newRules` 数组末尾添加（注意逗号）：

```json
    ,
    {
      "prefix": "Z5801G",
      "model": "ZEPHYR RTX 5080 16G 深渊"
    }
```

### 旧 SN（放进 `oldRules`）

```json
    ,
    {
      "prefix": "ZF5801",
      "model": "ZEPHYR RTX 5080 16G 浪花"
    }
```

**字段说明：**

- `prefix`：SN 开头的料号，必须与真实 SN 一致（区分大小写）
- `model`：查询结果中显示的产品型号

---

## 新增特例 SN

当某个 SN 不能靠自动规则解析，需要固定显示结果时，在 `exceptions` 里添加：

```json
    ,
    {
      "sn": "LH3602231120000019",
      "model": "浪花RTX3060 12G",
      "dateText": "2024年第42周"
    }
```

**字段说明：**

- `sn`：完整 SN，必须一字不差
- `model`：显示的产品型号
- `dateText`：显示的出厂日期文字（按实际填写，如 `2024年第42周` 或 `2024-10-15`）

---

## 修改已有料号

1. 在文件中搜索 `prefix` 或 `sn`
2. 只修改 `model` 或 `dateText` 的值
3. **不要改** `prefix` / `sn` 本身（除非料号规则变了）

---

## 删除料号

找到对应 `{ ... }` 整块删除即可。

删除时注意：

- 前一项或后一项的逗号不要多留
- 数组最后一项后面**不能有逗号**

---

## 常见错误

| 错误现象 | 原因 | 解决方法 |
|----------|------|----------|
| 保存后网站报错 / 校验失败 | JSON 格式错误 | 检查逗号、引号是否成对 |
| 查不到新型号 | 放错数组或 prefix 写错 | 确认在 `newRules`，且 prefix 与 SN 开头一致 |
| 特例不生效 | `sn` 不完全匹配 | 复制完整 SN，不要有空格 |
| 重复 prefix | 同一料号写了两次 | 搜索 prefix，只保留一条 |

---

## JSON 格式要点

1. 所有文字都要用英文双引号 `"` 包裹
2. 每个 `{ ... }` 块之间用逗号分隔
3. **最后一个** `{ ... }` 后面不要加逗号
4. 只改 `data/products.json`，**不要改**其他文件

## 改错了怎么办

GitHub 可以查看历史版本并恢复：

1. 打开 `data/products.json`
2. 点击 **History**
3. 找到改之前的版本
4. 点击 **Revert** 或复制旧内容重新提交
